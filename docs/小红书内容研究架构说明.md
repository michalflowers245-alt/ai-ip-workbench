# 小红书内容研究架构说明

## 目标与边界

这个模块把“输入主题”变成一条可追踪的本机研究任务：浏览器执行真实搜索，采集可访问的原帖链接，逐条打开详情页，提取文字与可见指标，再将结果和诊断保存到 SQLite。自动监控可按账号定位关键词每 6、12 或 24 小时启动一轮，服务重启后按持久化的下一次运行时间恢复。它不使用虚假的搜索 API，不绕过登录、验证码、付费或平台安全机制，也不读取和导出用户凭据。

热点证据核验对新闻媒体使用精确主机名白名单。Euronews 与 Euronext 已纳入正文抓取，证据类型为“媒体报道”，不会被标成公司官方声明；添加其他来源前需验证站点和归属。未接入域名仍保留链接并转为手动核对，禁止为提高覆盖率而开放任意网页抓取。

## 各组件如何协作

### Agent

工作台里的 Agent 负责把研究结果用于后续选题和文案。它不直接控制登录凭据，也不把模型生成内容当成原帖。只有页面采集完成后，本机模型才可以对已提取文本做去重和排版清洗。原始字段、字段来源和失败诊断始终单独保存。

### Playwright

Playwright 是浏览器自动化层。`XhsBrowserController` 用 `launchPersistentContext` 启动系统 Chrome，并把用户数据保存在独立目录。它完成打开首页、输入关键词、提交搜索、有限滚动、链接去重、顺序打开详情和截图。默认可见浏览器便于用户完成扫码或安全验证；测试环境可以用 `XHS_HEADLESS=1`。

### DOM（文档对象模型）

DOM 是第一层正文提取入口。提取器先读取 JSON-LD 和网页元数据，再按语义选择器寻找标题、作者、正文、发布时间、标签和可见互动数据。遇到“展开正文”或“全文”按钮会先点击，再重新读取。指标只在标签和数字明确对应时解析，避免把日期误判成点赞数。

### Accessibility Tree（无障碍结构树）

当常用 DOM 选择器失效且结构化正文为空时，提取器读取页面无障碍快照。它能在 class 名变化后保留一层可访问文本兜底。结果卡会显示字段来源，方便判断某个字段来自结构化数据、DOM、无障碍结构树还是普通可见文字。

### OCR（光学字符识别）

当帖子包含图片且网页正文较短时，系统截取页面中可见的大图并调用本机 OCR。macOS 使用 Vision 框架识别简体中文和英文；其他系统支持安装了 `chi_sim` 的 Tesseract。OCR 不可用、运行失败或没有识别到文字是三个不同状态，页面会分别解释原因。

### ASR（自动语音识别）

视频内容先读取页面可见字幕或可访问字幕轨。若网页没有字幕，只有当用户提供有权处理的本地媒体文件并且本机装有 Whisper/Faster-Whisper 时，适配器才允许继续转写。当前自动搜索链路不会绕过小红书限制下载视频，因此没有可用本地媒体时会明确显示“视频口播暂未提取”。

### SQLite

SQLite 是单一持久化层，数据库文件为 `data/xhs-research.sqlite`，包含六类表：

- `xhs_search_tasks`：关键词、目标数量、阶段、进度、成功/失败数和终止状态。
- `xhs_posts`：原帖 URL、标题、作者、正文、图片文字、字幕、指标、截图、完整度、来源和各适配器状态。
- `xhs_content_extractions`：每次提取的原始 JSON、合并文本、本机模型清洗结果和字段来源。
- `xhs_task_posts`：任务与去重帖子的多对多关系。
- `xhs_task_errors`：失败阶段、最终 URL、页面标题、截图、文本长度、定位器数量，以及登录、验证和平台限制判断。
- `xhs_automation_settings`：监控词、刷新间隔、每词目标数、启停状态、下一次运行时间和最近一次结果状态。

帖子以标准化后的 URL 做唯一约束。同一原帖可以出现在不同关键词任务中，不会复制成多份帖子记录。工作台重启时，正在运行的任务会标记为“被重启中断”，已经完成的帖子继续保留。

自动关键词任务通过 `xhs_search_tasks.source=automation` 与手动搜索区分。调度器同一时刻只运行一轮，并复用浏览器采集队列；每轮最多 5 个词，每词最多 20 条，默认每 12 小时一次、每词 5 条。首次启用需要已核验的登录状态；配置可先保存为“等待登录”。检查到登录失效、验证、平台限制或连接异常后，调度器清空 `next_run_at` 并暂停，不会持续重试。本人完成登录/验证并再次检查后才恢复。

这个自动化只代表本机对关键词搜索结果的定时复查，不代表官方全站热榜 API，也不保证搜索排序就是平台热度排名。机器关机、休眠或工作台服务退出时不运行；重启后最多补一次已到期的采集，不连续补跑错过的周期。页面发布时间和指标只记录页面能读取到的字段，空缺会保留为空。

### API（应用程序接口）

浏览器页面不直接操作 Playwright 或数据库，只调用本机 HTTP API。创建手动任务后服务器异步执行，前端每 1.2 秒读取一次任务状态；终态后停止轮询。`GET|POST /api/xhs/automation` 读取或更新持久化监控设置。调度器以 30 秒为检查粒度，但只在达到下一次运行时间时启动采集。用户可以暂停监控或停止当前任务，服务在当前安全节点结束。重新提取会复用原帖 URL 并递增重试次数。

## 任务状态

```text
queued → opening_browser → searching → extracting → completed
                                             ├→ partial
                                             ├→ failed
                                             ├→ needs_login
                                             ├→ needs_verification
                                             └→ stopped
```

任务级状态和帖子级提取状态分开。部分帖子成功、部分失败时，任务为 `partial`，成功结果仍可使用。登录或安全验证在搜索页或详情页出现时会停止继续请求，并给用户明确的恢复动作。

## 安全和性能策略

- 专用 profile 与普通 Chrome 用户目录隔离。
- API 只接受同端口本机页面的写操作，代理地址也只允许回环地址。
- 不返回 Cookie、Token 或密码字段。
- 最大目标数 20，详情并发为 1，滚动最多 12 次，连续三次没有新链接即停止。
- 每张详情页处理完立即关闭；服务退出时关闭持久浏览器和 SQLite。
- 截图接口只允许预设目录名和安全文件名，防止路径穿越。

## 已知限制与维护入口

平台前端更新可能使搜索框或内容选择器失效。此时先看结果卡和 `xhs_task_errors` 中的失败阶段、页面标题、最终 URL、文本长度、定位器数量与失败截图，再更新 `lib/xhs-extractor.js` 或 `lib/xhs-research.js` 的选择器。不要通过增加无限重试、高并发或规避验证来掩盖结构变化。
